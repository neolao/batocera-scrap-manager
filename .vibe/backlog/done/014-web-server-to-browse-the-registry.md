# Web Server To Browse The Registry

## Description
The registry can only be browsed today through the static HTML site regenerated by `update` (items 007/008/010), which allows no interaction. A new `serve` command must start an HTTP server delivering the registry's content from the program itself: a page listing the games grouped by system, and one page per game displaying its metadata and its cover art. That command is the foundation of the editing items that follow (015, 016, 017); at this stage it stays read-only. The static site keeps existing in parallel, unchanged.

## Acceptance Criteria
- [ ] `serve` starts an HTTP server listening on `0.0.0.0:8080` by default, prints the listening address at startup, and `--addr` changes the address and port
- [ ] The home page lists every game of the registry grouped by system, with name, short description and cover art, and gives access to a game's page
- [ ] A game's page displays its full metadata (description, rating, year, developer, publisher, genre, number of players) and its available media
- [ ] A game URL naming an unknown system or an unknown game answers 404 rather than an empty page or a server error
- [ ] `serve --help` prints the command's own help without requiring a configured registry, and `serve` with no configured registry prints the usual error message

## Notes
A game is identified in the URLs by the same key as the one used on disk: the ROM's base name without its extension (`gameID` in `internal/registry/registry.go`), so no second matching rule is introduced (see `decisions/014`). Media are served from the registry folder through an `http.FileServer` (which neutralizes path traversal). The static site's styling and formatting helpers (`groupBySystem`, `formatStars`, `formatYear`, `escapeMediaPath` in `internal/site/site.go`) must be reused rather than duplicated. New `internal/webui` package for the handlers and templates, command in `internal/cli/serve.go` following the pattern of the existing commands (`--help` handled first, `loadConfigAndRegistry`). Tests through `net/http/httptest`, without opening a port.
