# Module: site
**Role:** Shared presentation layer of the registry: turns its entries into HTML views (grouping by system, rating stars, release year, safely encoded media paths, theme) and generates the styled static HTML site to browse the registry's content (games grouped by system, with name, description, and jaquette, sticky horizontally-scrolling navigation between systems, click-to-expand full game details including metadata and video) in a web browser.
**Files:** `internal/site/site.go`, `internal/site/view.go`, `internal/site/style.css`, `internal/site/modal.css`
**Exports:**
- `site.Generate(reg *registry.Registry, registryFolder string) error` — groups `reg`'s entries by system (sorted alphabetically, games sorted by name within each system for deterministic output) and writes `<registryFolder>/index.html`, directly at the registry's root. Each game card shows its name, its release year when known, and a clamped description — the year being what tells two releases apart once the description is hidden on a phone. Each system is rendered as an anchored section (`id="<system>"`) linked from a sticky navigation bar (scrolling horizontally, rather than wrapping, when many systems are configured), and each game as a styled card with a clamped (truncated) description; a game without a jaquette, or whose referenced jaquette/video file no longer exists on disk in the registry folder, renders a placeholder card art instead of a broken `<img>`/`<video>`. Each card links to a per-game detail overlay showing its full, untruncated description plus rating (as stars), release year, developer, publisher, genre, players, and gameplay video (when available and present on disk), shown/hidden with a pure-CSS `:target` technique (no JavaScript) — see [`decisions/010`](../decisions/010-css-only-detail-modal-via-target.md). The overlay's close controls link to a non-existent anchor so closing it never scrolls the page — see [`decisions/011`](../decisions/011-void-anchor-to-close-modal-without-scrolling.md). Every system section ends with a link back to the top of the page. An empty registry still produces a valid page, with a "No games in the registry yet." message. Media (jaquette, video) references are resolved relative to the generated page as `<system>/<path>`, with each path segment percent-encoded so file names containing spaces, brackets, or parentheses still produce valid links, mirroring where `registry.ImportFromRomsFolder` copies media under the registry folder. The page's CSS is embedded inline in a `<style>` block (no external stylesheet), including a responsive rule so the layout stays readable on small screens.

- `site.GroupBySystem(entries []registry.Entry, registryFolder string) []SystemView` — groups entries by system (systems sorted by name, games by name within each) and precomputes each game's rendering fields; the single grouping/formatting entry point of both renderings
- `site.SystemView{Name, Games}` / `site.GameView{Game, ID, System, ImagePath, VideoPath, MarqueePath, ThumbnailPath, Stars, RatingLabel, Year}` — the view types produced by `GroupBySystem`. Each media path is percent-encoded and relative to the registry folder (`<system>/<relPath>`), and left **empty** when the referenced file is not actually on disk — that emptiness is how both renderings detect a missing medium. `ID` is `registry.GameID(Game.Path)`, `RatingLabel` the rating in words (`"4/5"`) matching `Stars`, so the value is never conveyed by star glyphs alone
- `site.FormatStars(rating string) string`, `site.FormatYear(releaseDate string) string`, `site.EscapeMediaPath(system, relPath string) string`, `site.MediaFileExists(registryFolder, system, relPath string) bool` — the individual formatting/lookup helpers behind `GroupBySystem`, exported for renderings that need one in isolation
- `site.FilledStars(rating string) (int, bool)` / `site.RatingFromStars(filled int) string` and `site.FormatYear` / `site.ReleaseDateFromYear(year string) string` — the two lossy display formats and their inverses, kept in the same file so the two directions cannot drift apart. A rating is corrected as the star count it displays as, a release date as its year alone; `RatingFromStars(0)` is `"0"` (five empty stars), distinct from `""` (not rated), and `ReleaseDateFromYear` defaults the day and month to 1 January — see [`decisions/019`](../decisions/019-edit-the-displayed-formats-not-the-stored-ones.md)
- `site.StyleSheet template.CSS` — the theme shared by every HTML rendering (embedded from `style.css`): theme variables, header, sticky system navigation, card grid, responsive rules. Below 640px the grid becomes a **bordered list of compact rows** — the card turns into a 3.5rem row holding a square thumbnail, the game name and its release year (`.card__meta`), with the description hidden — because a full-width card with a 4:3 cover fits about one game per phone screen; below 480px the navigation pills also grow to a 2.75rem tap target. Both renderings get this at once, which is the point of the shared sheet (backlog item 020). The static site's own `:target` overlay rules live apart, in `modal.css`, and are appended by `Generate` only — see [`decisions/016`](../decisions/016-share-the-presentation-layer-from-internal-site.md)

**Depends on:** [`modules/registry.md`](registry.md), [`modules/gamelist.md`](gamelist.md)

**Architecture note:** Added for backlog item 007. Rendering uses Go's `html/template` (not `text/template`) so game names/descriptions are auto-escaped, since they originate from user-editable `gamelist.xml` files. Regeneration is not exposed as its own CLI command — see [`modules/cli.md`](cli.md) and [`decisions/006`](../decisions/006-auto-regenerate-html-site-on-update.md): it is instead triggered automatically at the end of the `update` command, the only command that actually mutates the registry. The generated page moved from a `site/` subfolder to the registry root for backlog item 008 — see [`decisions/008`](../decisions/008-move-consultation-site-to-registry-root.md); a `site/` folder left over from a previous version is never auto-deleted, by explicit product decision. The navigation bar is sticky (stays visible while scrolling) rather than a one-time summary block, for backlog item 010 — see [`decisions/009`](../decisions/009-sticky-navigation-bar-on-consultation-site.md). The generated page stays JavaScript-free by using a CSS-only `:target` show/hide technique for the per-game detail overlay — see [`decisions/010`](../decisions/010-css-only-detail-modal-via-target.md) and [`decisions/011`](../decisions/011-void-anchor-to-close-modal-without-scrolling.md). Media paths are built with a dedicated helper that percent-encodes each path segment (`net/url`'s `PathEscape`) instead of relying on `html/template`'s own URL context escaping, because the latter deliberately leaves characters like `[` and `]` unescaped in URL attributes, which some HTTP servers mishandle. `groupBySystem` checks each referenced jaquette/video file's presence on disk (`os.Stat` under the registry folder) before building its (percent-encoded) URL, since a game's metadata can reference a file the registry no longer actually has; a missing file is treated the same as no file at all (placeholder card art, no video player). Card jaquettes use `loading="lazy"` and every video uses `preload="none"`, so a large registry does not make the browser fetch every game's media on page load — without these, the page became noticeably slow to open as the registry grew, since every jaquette and video (even ones off-screen or inside an unopened detail overlay) was fetched eagerly.

**Architecture note (backlog item 014):** `internal/site` was widened from "generates a static file" to "renders the registry as HTML", so [`modules/webui.md`](webui.md) reuses its grouping, formatting and theme instead of duplicating them — see [`decisions/016`](../decisions/016-share-the-presentation-layer-from-internal-site.md). The view layer moved to `view.go` and the inline `<style>` block to two embedded stylesheets (`style.css` shared, `modal.css` static-site only), injected into the template through a `stylesheet` template function; `site_test.go` was left untouched by that refactor and is the regression guard proving the generated page did not change.
